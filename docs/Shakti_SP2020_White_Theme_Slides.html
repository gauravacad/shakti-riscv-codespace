Step 1: Download & Directory Setup

Clone SP2020 & Navigate to Pinaka SoC (E32-A35)

Step 2: Compatibility Fixes

Fix BSC GHC Heap, GCC ABI & Multiplier

Open-source environments require 3 minor adjustments to prevent BSC heap crashes and multilib GCC ABI mismatches.

A. Fix BSC Stack Integer Overflow (-K40000M → -K4000M)
sed -i 's/-K40000M/-K4000M/g' Makefile
sed -i 's|-verilog-filter [^ ]*||g' Makefile
B. Fix GCC ABI in Boot Code (-mabi=ilp32 & remove picolibc)
sed -i 's/--specs=picolibc.specs//g' boot-code/Makefile
sed -i 's/-march=rv$(XLEN)imac/-march=rv$(XLEN)imac -mabi=ilp32/g' boot-code/Makefile
C. Pipelined Multiplier Primitive
Creates common_verilog/multiplier.v resolving mkmuldiv.v unelaborated module.
Step 3: BSV to Verilog Generation

Compile Bluespec BSV to Cycle-Accurate Verilog

The Bluespec Compiler (BSC 2024.07) generates standard IEEE Verilog files for the processor core and full Pinaka SoC.

generate verilog
# Generate Verilog modules from Bluespec:
make generate_verilog CONFIG=core_config.inc
Verilog Modules Generated (`verilog/*.v`):
mkSoc.v mkeclass.v mkriscv.v mkmuldiv.v mkuart.v mkicache.v / dcache.v
Step 4: The 81.5x Acceleration Trick

Accelerate UART to 32 Clocks/Bit (Baud = 2)

Physical 19,200 Baud takes 2,608 clock cycles per bit (crawling in simulation). We configure the software baud divisor to 2 (32 cycles/bit), speeding up simulation by 81.5x with zero RTL alterations!

🐢 Physical 19,200 Baud:
Divisor = 163
2,608 cycles / bit
26,080 cycles / char (~15s per char in VVP)
⚡ Fast Simulation Baud (Divisor = 2):
Divisor = 2 (16 × 2)
32 cycles / bit
320 cycles / char (Streams in 3–5 seconds!)
# Apply fast simulation baud divisor & build Boot ROM image:
sed -i 's/\b163\b/2/g' boot-code/*.c boot-code/*.h 2>/dev/null || true
make generate_boot_files CONFIG=core_config.inc
Step 5: Prepare Simulation Workspace

Create `sim_baud_fix` & Preload Memory Files

Create an isolated simulation directory, copy the freshly built boot.mem, and create zero-fill memory files so Verilog memory loaders initialize cleanly.

setup simulation files
mkdir -p sim_baud_fix
cp boot-code/outputs/boot.mem sim_baud_fix/boot.mem
touch sim_baud_fix/code.mem sim_baud_fix/code1.mem
💡 BRAM2BELoad.v uses $readmemh to initialize RAM. Touching these files ensures zero missing-file errors.
Step 6: Compile SoC with Icarus Verilog

Build Cycle-Accurate Model (`shakti_soc.vvp`)

Elaborate all Verilog modules, Bluespec library primitives, and the fast-baud testbench into the executable simulation file.

iverilog build
iverilog -g2012 \
  -o sim_baud_fix/shakti_soc.vvp \
  -I /usr/local/lib/Verilog -y /usr/local/lib/Verilog \
  -I verilog -y verilog \
  -I common_verilog -y common_verilog \
  -I devices -y devices -I fabrics -y fabrics \
  baud_fix/multiplier.v baud_fix/uart_rx_monitor.v baud_fix/tb_soc_baud_fix.v \
  verilog/*.v
Binary Output Created: sim_baud_fix/shakti_soc.vvp READY
Step 7: Run Cycle-Accurate Simulation

Execute `vvp` (Verilog Virtual Processor)

Run the simulation executable using vvp. The testbench drives the 50 MHz clock, releases reset, and streams the UART console output.

run simulation
cd sim_baud_fix
vvp shakti_soc.vvp
⚡ Simulation Execution: At 32 cycles/bit, the entire ASCII Flame Logo and Pinaka banner display in 3 to 5 seconds!
