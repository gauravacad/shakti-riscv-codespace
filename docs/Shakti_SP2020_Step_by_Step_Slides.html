Step 1: Download & Directory Setup

Clone Authentic SP2020 & Navigate to E32-A35

Clone the official IIT Madras Swadeshi Microprocessor Challenge (SP2020) repository containing the Pinaka SoC design and enter the hardware workspace.

# 1. Clone repository from GitLab
git clone https://gitlab.com/shaktiproject/sp2020.git
# 2. Enter Pinaka SoC (Artix-7 35T) directory
cd sp2020/e32-a35
🎯 Board Target:

Pinaka SoC configured for Xilinx Artix7-35T FPGA.

📂 Core Contents:

Contains Bluespec BSV RTL, AXI4 fabrics, Boot ROM, and memory.

Step 2: Essential Compatibility Patches

Fix GHC Heap, GCC ABI & Multiplier Model

Open-source environments require 3 minor patches to prevent BSC memory overflow and GCC ABI conflicts.

// A. Fix BSC Compiler Heap Overflow (-K40000M -> -K4000M)
sed -i 's/-K40000M/-K4000M/g' Makefile
sed -i 's|-verilog-filter [^ ]*||g' Makefile
// B. Fix GCC ABI in Boot Code (-mabi=ilp32 & remove picolibc)
sed -i 's/--specs=picolibc.specs//g' boot-code/Makefile
sed -i 's/-march=rv$(XLEN)imac/-march=rv$(XLEN)imac -mabi=ilp32/g' boot-code/Makefile
// C. Provide 4-Stage Multiplier Primitive
Creates common_verilog/multiplier.v resolving mkmuldiv.v unelaborated module.
Step 3: BSV to Verilog Generation

Compile Bluespec (BSV) to Cycle-Accurate Verilog

The Bluespec Compiler (BSC 2024.07) compiles high-level BSV source code into pure IEEE Verilog files for the processor core and AXI interconnect.

# Generate Verilog modules using core configuration
make generate_verilog CONFIG=core_config.inc
Generated Verilog Outputs (`verilog/*.v`):
• mkSoc.v
• mkeclass.v
• mkriscv.v
• mkmuldiv.v
• mkuart.v
• mkicache.v / mkdcache.v
Step 4: The 81.5x Acceleration Trick

Accelerate UART to 32 Clocks/Bit (Baud = 2)

At physical 19,200 Baud, each bit requires 2,608 clock cycles. By setting software baud divisor to 2, transmission is 81.5x faster with zero hardware RTL alterations!

🐌 Real Physical 19,200 Baud: Divisor = 163
2,608 cycles / bit
26,080 cycles / char (~15s/char in VVP)
⚡ Fast Simulation (Divisor = 2): Divisor = 2 (16 * 2)
32 cycles / bit
320 cycles / char (Streams in 3-5s!)
# Apply fast simulation baud divisor (2) and compile Boot ROM
sed -i 's/\b163\b/2/g' boot-code/*.c boot-code/*.h 2>/dev/null || true
make generate_boot_files CONFIG=core_config.inc
Step 5: Prepare Simulation Workspace

Setup `sim_baud_fix` & Memory Preload Files

Create an isolated directory for the simulation, copy the generated boot.mem, and create zero-fill memory files to satisfy Verilog memory loaders.

# 1. Create clean simulation folder
mkdir -p sim_baud_fix
# 2. Copy compiled Boot ROM hex image
cp boot-code/outputs/boot.mem sim_baud_fix/boot.mem
# 3. Create dummy RAM preload files (prevents $readmemh fatal errors)
touch sim_baud_fix/code.mem sim_baud_fix/code1.mem
💡 Note: BRAM2BELoad.v uses $readmemh to initialize memory on startup. Touching these files ensures clean initialization.
Step 6: Compile SoC with Icarus Verilog

Build Simulation Executable (`shakti_soc.vvp`)

Compile the entire Pinaka SoC Verilog tree, Bluespec primitives, and the fast-baud testbench with iverilog.

# Elaborate SoC and build binary model:
iverilog -g2012 \
  -o sim_baud_fix/shakti_soc.vvp \
  -I /usr/local/lib/Verilog -y /usr/local/lib/Verilog \
  -I verilog -y verilog \
  -I common_verilog -y common_verilog \
  -I devices -y devices -I fabrics -y fabrics \
  baud_fix/multiplier.v baud_fix/uart_rx_monitor.v baud_fix/tb_soc_baud_fix.v \
  verilog/*.v
📦 Output Generated: sim_baud_fix/shakti_soc.vvp SUCCESS
Step 7: Run Cycle-Accurate Simulation

Execute `vvp` (Verilog Virtual Processor)

Run the simulation executable using vvp. The testbench releases reset at 200ns, drives the 50 MHz clock, and decodes the 32-clock serial bitstream.

# Enter simulation directory and run:
cd sim_baud_fix
vvp shakti_soc.vvp
⚡ Execution Speed:

Because `CLKS_PER_BIT = 32`, characters stream out smoothly in 3 to 5 seconds instead of crawling for minutes!
